# NATS の送受信のテスト

NATS JetStream を使う送受信（`crates/ashiato-nats`）のテストのうち、NATS サーバーを使うものは、NATS サーバーを Docker で動かして実行する。Docker を必要とするので、`#[ignore]` を付けて `cargo test` から外している。

メッセージとヘッダーの変換、ストリームとコンシューマーの設定、`max_bytes` の検査（`crates/ashiato-nats/tests/codec.rs`、`config.rs`）は、NATS サーバーを使わないので、通常の `cargo test` で実行される。

## NATS サーバーの版

サブジェクトごとの上限に達したときに新しいメッセージを拒否する設定（`discard_new_per_subject`）は、NATS サーバー 2.9.1 以降で使える。2.9.0 のサーバーは、この設定を指定してストリームを作っても設定に残さず、上限に達したサブジェクトへの新しいメッセージを拒否しない。この場合は流量の制御（`streaming-pipeline.md` の 7.2 節、9 節）が働かないので、2.9.0 以前のサーバーは使えない。

テストは、2.10 系の版に固定した `nats:2.10.29` のイメージを使う。初回は次のコマンドで取得しておく。

```sh
docker pull nats:2.10.29
```

テストで起動する NATS サーバーは、JetStream の設定で `sync_interval: always` を指定する（`streaming-pipeline.md` の 7.1 節）。

## 実行

```sh
cargo test -p ashiato-nats -- --ignored
cargo test -p ashiato-cli --test distributed -- --ignored
```

`ashiato-cli` のテストは、`ashiato run` と `ashiato ingest-worker` を別々のプロセスとして起動し、ソースには MinIO を使う。MinIO のイメージの取得は `docs/s3-testing.md` に書いた。

テストは、テストごとに NATS サーバーのコンテナを 1 つ起動し、テストが終わるとき（失敗した場合を含む）にコンテナを削除する。JetStream の保存先はコンテナの中に置くので、コンテナを再起動してもストリームは残り、コンテナを削除すればデータは残らない。NATS サーバーのポートは `127.0.0.1` の空いているポートに割り当てる。コンテナを再起動しても同じポートで待ち受けるように、ポートは Docker に選ばせず、テストが選んで指定する。

テストのプロセスを強制終了した場合は、コンテナと、一時ディレクトリに置いた NATS サーバーの設定ファイルが残ることがある。残ったコンテナは、ラベルを指定して削除する。

```sh
docker rm --force $(docker ps --quiet --filter label=ashiato-test=nats)
```

テストが起動した `ashiato` のプロセスは、テストが失敗した場合も止める。テストのプロセスを強制終了した場合は残ることがあるので、`ps` で確かめて止める。

## 確かめていること

- `crates/ashiato-nats/tests/nats.rs`
  - ストリームとパーティションごとのコンシューマーが、`streaming-pipeline.md` の 7.1 節の設定で作られる。
  - `max_bytes` がパーティションの数 × `max_messages_per_partition` × `max_message_size` より小さいと、ストリームを作る前にエラーになる。
  - パーティションのメッセージが `max_messages_per_partition` に達すると、取り込みワーカーの送信は、分析コンシューマーが確認応答を返すまで待つ。
  - NATS を通した分析コンシューマーの表が、チャネルを通した場合と一致し、終了時にストリームにメッセージが残らない。
  - `ack_wait` を短くして再配信を起こしても、分析コンシューマーの表が変わらない。
  - 分析コンシューマーを確定の前に止めて再開すると、確認応答を返していないメッセージを受け取り直し、表が変わらない。
  - NATS サーバーを途中で再起動しても、分析コンシューマーの表が変わらない。
  - ストリームからメッセージを 1 つ消して位置の穴を作ると、コンシューマーを 1 回作り直した後にエラーになる。
  - パーティションごとに、ストリームに残っている最後のメッセージの次の位置が求まる。
- `crates/ashiato-nats/tests/control.rs`
  - 分析コンシューマーが、ワーカー用の実行の定義と、確定した位置を答える。範囲外のワーカー ID には、理由を付けて断る。
  - 1 つの応答に収まらない一覧を、応答の大きさに収まるページに分けて返し、取り込みワーカーが全件を集める。
  - 分析コンシューマーが答えるまで、取り込みワーカーは要求を送り直す。
- `crates/ashiato-cli/tests/distributed.rs`
  - 分散の配置の出力とワークスペースの表が、1 プロセスの配置と一致し、終了時にストリームが消えている（`streaming-pipeline.md` の 14.1.3 節の 1〜3）。
  - 取り込みワーカーをファイルの途中で止めて再起動しても、出力と表が一致する。
  - 範囲外のワーカー ID で起動した取り込みワーカーは、エラーで止まる。
